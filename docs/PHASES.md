## Phase 02 — BASS BOOST ENGINE（低音EQ・サブベース・BYPASS）

**信号経路**

```
source → input ─┬─ dry(1/0) ───────────────────────────────────────────────────────────┬─ output → 音量 → 出力
                └─ HPF 22Hz → LowShelf 120Hz → Peak 80Hz → Peak 45Hz
                     → 出力補正(trim) → DynamicsCompressor → メイクアップ打消し → wet(0/1) ┘
```

**実装内容**
- `src/audio/processingGraph.ts`: EQ チェーンと処理グラフ。リアルタイム再生・ラウドネス計測・（Phase 04）書き出しで共通
- **BASS BOOST**（0〜100%）: LOW SHELF 120 Hz 0〜+6 dB ＋ PEAK 80 Hz（Q 1.0）0〜+3 dB
- **SUB BASS**（0〜100%）: PEAK 45 Hz（Q 1.4）0〜+9 dB。SUBSONIC HPF 22 Hz（Butterworth）は処理経路で常時有効
- **出力ゲイン補正**: 解析用抜粋（≦45 秒は全体、超える場合は 20/50/80% 位置の 15 秒×3）を OfflineAudioContext で EQ に通し、BS.1770 K特性・ゲーティング付き統合ラウドネスとサンプルピークを原音と比較。`trim = -max(ラウドネス増加, ピーク増加×0.5, 0)`、下限 -15 dB。正方向には補正しない
- **ピーク対策コンプレッサー**: DynamicsCompressorNode（しきい値 -3 dBFS / 12:1 / ニー 3 dB / アタック 2 ms / リリース 120 ms）。**リミッターではない**
- **メイクアップ打消し**: DynamicsCompressorNode の自動メイクアップゲイン（Chrome/Edge 実測 +1.10 dB）を起動時にオフライン実測して打ち消す
- **BYPASS**: dry/wet の 40 ms 線形クロスフェード。dry 経路はゲイン 1 のみ。B キーでも切替
- パラメーター変更は setTargetAtTime（時定数 30 ms、補正は 80 ms）で平滑化
- UI: スライダー（dB 表示付き）、実ノードから取得した周波数特性グラフ、補正量・ラウドネス/ピーク増加表示、ゲインリダクションメーター、信号経路表示
- DSP 自己診断: `npm run test:dsp`（`tests/dsp-selftest.html` をヘッドレス Chrome/Edge で実行）

**完了条件**
- [x] BASS BOOST / SUB BASS スライダーが処理ノードに接続され、再生音へ反映される（自己診断＋アプリ操作で確認）
- [x] BYPASS 時に原音とサンプル単位で完全一致する（自己診断: 最大差 0、5 種の信号）
- [x] BASS BOOST と SUB BASS の担当帯域が異なる（BASS: 80 Hz +7.9 dB / 120 Hz +4.8 dB、SUB: 45 Hz +8.8 dB / 120 Hz +0.9 dB）

- [x] ブーストで全体ラウドネスが上がらない（最大設定で原音 -9.35 → 処理 -9.36 LUFS）
- [x] 最大設定でクリップしない（-0.45 dBFS の高レベル信号で処理後 -1.39 dBFS）

## Phase 02.5 — EXTREME BASS ENGINE

### 原因調査（Phase 02 実装、楽曲相当信号・BASS/SUB 100%）

| 信号 | 段階 | SUB 20–60 | BASS 60–120 | 中域 200–2k | 高域 2–10k |
| --- | --- | --- | --- | --- | --- |
| EDM相当 | EQ のみ | +14.9 | +10.3 | +0.3 | 0.0 |
| | EQ＋出力補正（-12.0 dB） | +2.9 | -1.7 | -11.7 | -12.0 |
| | 実出力（＋コンプ） | +2.1 | -2.8 | -12.2 | -12.5 |
| アコースティック相当 | 実出力（補正 -3.5 dB） | +10.9 | +5.8 | -3.6 | -3.8 |

- EQ 設定は実ノードに正しく反映（正弦波実測で設計値と一致）、BYPASS も正常（原音とサンプル一致）
- **主因: 全帯域ラウドネス一致の出力補正**。低域主体の曲では EQ の増加分とほぼ同量を全帯域から引くため、低域の絶対レベルはほぼ変わらず、中高域だけが大きく下がる（EDM相当で -12 dB、出力は原音より 0.9 LU 小さい）。BYPASS 切替が「音量差」に聞こえる原因
- コンプレッサーによる低域の損失は約 -1 dB（副次的）

### 対策

- 信号経路: `HPF(4次) → EQ → LR4 クロスオーバー 150 Hz → [低域コンプ] + [中高域] → 全帯域トリム → サンプルピークリミッター(-1 dBFS, 先読み 5 ms)`（ダイナミクスは AudioWorklet）
- 出力補正を「中高域維持（mid-anchor）」に変更: ピークはまず低域コンプのしきい値を下げて低域側で吸収し、全帯域トリムは目標・下限内に限定。予算内に収まらない設定は EQ 実効値を自動で縮小（安全制限）。Phase 02 方式は「ラウドネス一致（A/B比較用）」として選択可能
- EXTREME モード: シェルフ 100 Hz +10 / 80 Hz +8 / 50 Hz +9（合成上限 +24 dB）。40 Hz 中心より 50〜100 Hz 中心の方が同じピーク予算で 60–120 Hz が上がることを比較で確認して決定
- スペクトル比較パネル: 解析抜粋を実際の処理グラフでオフライン処理した平均スペクトル、20–200 Hz の 1/3 オクターブ変化、帯域別変化

| モード | EQ（最大） | 低域コンプ | リミッター予算 | トリム目標 / 下限 | ラウドネス増加上限 |
| --- | --- | --- | --- | --- | --- |
| NORMAL | シェルフ 120 Hz +6 / 80 Hz +3 / 45 Hz +9（合成 ≤ +18） | 3:1、しきい値 原音低域ピーク +3〜-3 dB | 3 dB | -1.5 / -2 dB | +2 LU |
| EXTREME | シェルフ 100 Hz +10 / 80 Hz +8 / 50 Hz +9（合成 ≤ +24） | 8:1、しきい値 原音低域ピーク +2〜-9 dB | 8 dB | -0.5 / -3 dB | +4 LU |

### 結果（`npm run test:dsp`、Chrome / Edge で同一結果: 62 PASS / 1 FAIL）

| 信号（BASS/SUB 100%） | 方式 | 低域 20–120 | 60–120 | 中域 | ピーク |
| --- | --- | --- | --- | --- | --- |
| ポップス相当 | Phase 02 | +6.1 | +2.0 | -7.0 | — |
| | EXTREME | +5.5 | +3.5 | -3.2 | -1.00 dBFS |
| アコースティック相当 | Phase 02 | +10.0 | +5.8 | -3.6 | — |
| | EXTREME | +9.4 | +7.7 | -1.3 | -1.00 dBFS |
| EDM相当（低域飽和） | Phase 02 | +1.3 | -2.8 | -12.2 | — |
| | EXTREME | +0.3 | -0.7 | -3.3 | -1.00 dBFS |

- FAIL 1 件: EDM相当で 20–120 Hz の絶対値が Phase 02 より 1.0 dB 低い（判定「-1 dB 以内」の境界）。Phase 02 は中域を -12 dB 下げることでこの 1 dB を得ていた。低域がすでにピーク付近にある曲では、天井 -1 dBFS の下で低域の絶対レベルを上げる余地がほぼない（物理的制約）

## Phase 03 — Dynamic Spatial Motion Engine

固定された空間から「音が独立して動く空間」へ。詳細・測定結果は docs/SPATIAL.md。

**実装内容**
- レイヤー分解（STFT・AudioWorklet）: CENTER / LEFT / RIGHT / AMBIENCE ＋ 低域 BED。全レイヤーの和 = 原音
- MOTION ENGINE: 位置はメディア時刻の純粋関数（乱数なし）。12 方向の固定 HRTF 仮想スピーカーへの等パワーパンで移動（HRTF 自体は動かさない）
- DISTANCE ENGINE: 逆距離ゲイン・空気吸収ローパス・伝搬遅延。反射・残響は原音から作り、距離で直接音/残響比と時間差が変わる
- CENTER LOCK: 中央成分の抽出強度。CENTER と BED は常に前方固定
- プリセット: CINEMATIC MOTION / ORBIT / SWEEP / PULSE（PULSE は曲全体から事前計算した包絡）
- UI: MOTION ENABLE / PRESET / SPEED / DEPTH / CENTER LOCK、DSP の実際の位置を表示する Spatial Position Visualizer

## Phase 04 — Immersive Audio Engine 2.0（Spatial Tail・Dynamic Tail・Loop）

「音が空間内で動き、広がり、演奏が止まった後も自然な余韻が残る」。詳細・測定結果は docs/SPATIAL.md。

**実装内容**
- 既存 HALL の余韻を解析し、ベースラインを保存（`src/dev/hallBaseline.json`、Phase 04 の変更前のコードで測定）
- SPATIAL TAIL（CINEMA / HALL）: NATURAL（既存 HALL と同じ IR）/ DISTANCE（暗く・狭く遠ざかる）/ RIPPLE（中央から外側へ広がる演出）。TAIL LENGTH・TAIL INTENSITY
- DYNAMIC TAIL: 演奏が密な間は残響を最大 8 dB 下げ、音の切れ目で戻す（Attack 25 ms・Hold 150 ms・Release 250 ms・平滑化 10 ms）。蓄積防止つき
- Motion と残響の統合: LEFT / RIGHT の初期反射への送りが音源の左右位置に追従。後期残響はモノラル送りのまま
- LOOP: NORMAL（ファイル全体、境界で前回の後期残響を消す）/ SPATIAL（音楽の区間、前回の余韻と次の冒頭を重ねる）
- STOP（直接音だけ 12 ms で止め余韻は残す）/ PAUSE（出力を 20 ms で止め残響を消す・位置保持）/ CUT（直接音・余韻とも 20 ms で止める）
- 副次的な修正: ランプが過去から始まる不具合（ORIGINAL/PROCESSED の 2 回目以降の切替で値が飛ぶ）、解析用の OfflineAudioContext が MessagePort の受信設定で解放されない不具合、解析の間引き（250 ms）

## Phase 06 — Audio Export Engine

## Phase 07 — Video Processing Engine

動画 → 音声の抽出 → 立体音響化（Phase 06 の書き出し）→ 音声だけの WAV、または映像はそのままで音声を差し替えた動画。処理はすべてブラウザ内（サーバーへ送らない）。方式の比較・同期の設計・測定結果は docs/SPATIAL.md。

**実装内容**
- 方式: WebCodecs + コンテナライブラリ mediabunny 1.61.3（MPL-2.0、改変なし・バージョン固定）。FFmpeg wasm は配布サイズ（64.7 MB）・ライセンス（GPL）・CLAUDE.md の「大規模ライブラリは要相談」のため不採用。動画を読み込んだときだけ遅延読み込み（gzip 約 122 KB）
- 読み込み: 拡張子 mp4 / m4v / mov / webm / mkv → 中身でコンテナを判定（拡張子だけでは判断しない）。映像・音声のコーデック、解像度、フレームレート、音声トラック（複数ある場合は主な音声トラックだけを使い、そう表示）。音声は WebCodecs でデコードし、各サンプルをタイムスタンプの位置に並べる（decodeAudioData は音声の開始時刻を失うため使わない）。音声のない動画・壊れた動画・非対応のコンテナはエラー表示
- 書き出し（VIDEO パネル）: ① 元の音声を WAV（DSP なし）② 立体音響化した WAV（Phase 06 と同じ、余韻を最後まで）③ 音声を差し替えた動画（映像は符号化済みのパケットをコピー、音声は MP4 / MOV → AAC、WebM / MKV → Opus）
- 動画の終わりの余韻: 既定は映像の長さを保つ（映像の終わりで切って 20 ms フェード）。選択で「最後のフレームを延ばして余韻を残す」（映像は再エンコードしない）
- 表示: ファイル名・コンテナ・コーデック・長さ・解像度・音声トラック・出力形式・推定サイズ・メモリの見積もり・段階（PREPARING / RENDERING / ENCODING / MUXING / PROCESSING COMPLETE）・キャンセル・ダウンロード・入力と完成動画のプレビュー（書き出したファイルをそのまま再生。再生用の DSP は通さない）
- メモリ: 動画ファイル 1 GiB まで、書き出し前の見積もりと上限、入力はファイル全体を読まない（Blob の部分読み込み）、レンダリング後に浮動小数点の音声を手放す、Object URL の解放、音声の書き出しと共通の二重実行の防止、失敗・キャンセル時に出力を破棄
